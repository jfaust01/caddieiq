# Data Provider Badges Implementation

## Objective

Display data provider information for every table in the Data Management > Platform Inventory view. This allows administrators to immediately identify which upstream system owns each table's data.

## Implementation Summary

### 1. Type Definitions (`lib/data-coverage/types.ts`)

Added new type for data provider sources:

```typescript
export type DataProvider = "sportsdataio" | "golfcourseapi" | "internal" | "multiple"
```

Extended `PlatformInventoryEntry` with:

```typescript
provider: DataProvider
```

### 2. Provider Configuration (`lib/data-coverage/provider-config.ts`)

Created centralized configuration file mapping all 31 database tables to their data provider sources:

**SportsDataIO (13 tables):**
- Tournament data: tournaments, tournament_courses, tournament_fields
- Player data: players, player_season_statistics, player_rounds
- Betting/Fantasy: betting_events, fantasy_projections, dfs_salaries
- News: news_articles

**GolfCourseAPI (11 tables):**
- Course data: courses, course_details, course_coordinates
- Course details: course_holes, course_tees, tee_hole_yardages
- Course metadata: course_specifications, course_metadata, playing_conditions

**Internal (11 tables):**
- Reference: tours, seasons, nationalities
- Generated intelligence: course_intelligence, player_intelligence, tournament_intelligence
- Auth/Users: users, profiles, sessions, accounts, verifications
- Operations: import_runs, audit_logs

**Multiple Providers (4 tables):**
- Odds data: odds_events, odds_quotes (The Odds API)
- Tournament mappings: tournament_course_mappings (SportsDataIO + GolfCourseAPI)
- Weather: weather_snapshots, weather_periods (OpenWeather)

### 3. Provider Badge Component (`features/admin/data-coverage/provider-badge.tsx`)

Visual component displaying provider information with:

- **Color-coded emoji badges:**
  - 🟦 SportsDataIO (blue)
  - 🟩 GolfCourseAPI (green)
  - 🟨 Internal (amber)
  - 🟪 Multiple Providers (purple)

- **Interactive tooltips** explaining each provider's purpose:
  - SportsDataIO: "Tournament, player, fantasy, scoring, betting, and schedule data."
  - GolfCourseAPI: "Course layouts, holes, tees, yardages, coordinates, and course metadata."
  - Internal: "Generated by CaddieIQ."
  - Multiple: "Data is merged from SportsDataIO and GolfCourseAPI."

### 4. Inventory Panel Updates (`features/admin/data-coverage/inventory-panel.tsx`)

Enhanced the Platform Inventory table:

- **New column:** "Provider" inserted between "Table" and "Owner"
- **Each row displays:** Provider badge with emoji, label, and tooltip
- **Table headers updated** to include the new Provider column

### 5. Data Generation (`lib/data-coverage/inventory.ts`)

Updated `buildPlatformInventory()` function to:

- Import `getProviderForTable()` from provider-config
- Assign provider for each table during inventory entry creation
- Include provider in the returned `PlatformInventoryEntry`

### 6. Module Exports (`lib/data-coverage/index.ts`)

Added provider-config exports to public surface:

```typescript
export * from "./provider-config"
```

## Future-Proofing

The provider information comes from a configuration object rather than being hardcoded in each row:

```typescript
export const PROVIDER_CONFIG: Record<string, DataProvider> = {
  tournaments: "sportsdataio",
  courses: "golfcourseapi",
  // ...
}

export function getProviderForTable(tableName: string): DataProvider {
  return PROVIDER_CONFIG[tableName] ?? "internal"
}
```

**Advantages:**
- Single source of truth for provider assignments
- Easy to update provider for a table (one location)
- New providers can be added without changing components
- Defaults to "internal" for unknown tables (safe fallback)
- Can be exported to admin tools, documentation, or APIs
