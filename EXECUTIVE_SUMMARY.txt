QUESTION 4: What is the root cause?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Answer: MISSING TYPE COERCION IN MAPPER

The Problem:
  // SportsDataIO Type Definition
  MadeCut?: boolean

  // Actual API Response
  { "MadeCut": 1.1 }  ← Returns FLOAT, not boolean!

  // Current Mapper Code
  const madeCut = player?.MadeCut ?? null
  // Passes raw 1.1 to Prisma
  // Prisma rejects: expects Boolean | Null, got Float

Why It Wasn't Caught:
  1. TypeScript interface says `boolean` but doesn't validate runtime values
  2. Mapper doesn't coerce the value
  3. Prisma catches it too late (at persistence time)
  4. No validation layer exists to bridge the gap


QUESTION 5: What is the fix?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Answer: COERCE TO BOOLEAN IN MAPPER ✅ APPLIED

File: lib/domain/round/mapper.ts

Before:
  const madeCut = player?.MadeCut ?? null
  // Passes raw value to Prisma (WRONG)

After:
  const rawMadeCut = player?.MadeCut
  const madeCut = rawMadeCut === undefined || rawMadeCut === null ? null : !!rawMadeCut
  // Coerces to boolean before Prisma (CORRECT)

How It Works:
  !! (double negation) converts any value to boolean
  - 1.1 becomes true
  - 0 becomes false
  - null/undefined becomes null
  - All results are Boolean | Null (what Prisma expects)
